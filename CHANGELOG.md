# Changelog

All notable changes to [`@workerstack/clients`](https://www.npmjs.com/package/@workerstack/clients), formerly `@lovrozagar/honey-clients`, are documented in this file. Releases up to 1.0.0-rc.23 shipped from the backend repository; their notes are in [its changelog](https://github.com/workerstack/backend/blob/main/CHANGELOG.md).

## [Unreleased]

### Added

- **The CLI checks WebSocket input against what the server receives, and prints typed streams.** Where a WebSocket operation declares its `receive`, a ws command checks each stdin line before it sends it: the line must be JSON that decodes as that type with its required fields, and for a union keyed on one field the member its key names. A line that fails is not sent; its refusal goes to stderr as any error does (`input line 2 not sent: …`), the conversation reads on, a blank line is skipped, and the run exits 4 (`input lines not sent: N`) when it ends. Each message prints as its type re-encodes it, a key value the operation does not declare as sent, and a frame that does not decode sends a close 1007 and ends the run with exit 1, where it was reported as a dropped connection. An event stream that names its events prints each by its name, an unnamed one as `message`. See [the generated CLI](docs/cli.md#streams).
- **The MCP server types each event of a stream's collect by its name.** When an SSE operation names its events, the collect's `outputSchema` requires each event's `event` and lists the declared names as its `examples`. Each JSON event's `data` gets its own `anyOf` member, keyed on its name (one `const`, or an `enum` for names that share a schema), and every other event, declared or not, has its `data` as a string. Before, every event's `data` was typed as a string, so a client that validated a collect refused a JSON event's parsed object. A stream that names no events is typed as before. `structuredContent` is unchanged.
- **The C# SDK types event streams and sockets from the document.** An SSE operation with named events yields `<Op>Event`, an abstract record with one nested sealed record per name holding `Data`, `Event`, `Id` and `Retry`, each JSON event decoded by its name, and `Unknown` for a name the operation does not declare, its data as text; an `is` match reads `Data` typed. A WebSocket operation with declared messages returns `TypedWebSocket<TIn, TOut>` and a realtime one `ResumableConnection<TIn, TOut>`, with `Message` beside the reader. When the messages are a union keyed on one field, the read side is `<Op>Inbound`, a nested record per member and `Unknown(JsonElement Raw)` for an undeclared value, with an `On<Value>` extension per member, and each member's record converts implicitly to `<Op>Outbound`; a member named like a handler is heard only through `Message`. An operation without typed events or messages reads as before.
- **The Java SDK types event streams and sockets from the document.** An SSE operation with named events yields `<Op>Event`, a sealed interface with one nested record per name holding `data`, `event`, `id` and `retry`, each JSON event decoded by its name, and `Unknown` for a name the operation does not declare, its data as text; an `instanceof` match reads `data()` typed. A WebSocket operation with declared messages returns `TypedWebSocket<TIn, TOut>` and a realtime one `ResumableConnection<TIn, TOut>`, with `onMessage` beside the reader. When the read side is a union keyed on one field, it is the sealed interface the models declare, with `<Union>Unknown` for an undeclared value, and the answer is `<Read>Socket<TOut>` or `<Read>Connection<TOut>`, whose `on<Value>` takes each member's handler, run inside the read; a member named like a handler is heard only through `onMessage`. An operation without typed events or messages reads as before, under the spelling Breaking names.
- **The Rust SDK types event streams and sockets from the document.** An SSE operation with named events yields `EventStream<<Op>Event>`, an enum with one variant per name, each holding `SseEvent<Data>` with its JSON decoded by the name, and `Unknown(SseEvent<String>)` for a name the operation does not declare. `SseEvent` and each event enum implement `Serialize`, as `{data, event, id, retry}`. A WebSocket operation with declared messages returns `TypedWebSocket<In, Out>` and a realtime one `ResumableConnection<In, Out>`, with `on_message` beside `recv`. When the messages are a union keyed on one field, the read side's enum keeps an undeclared value as `Unknown`, and `on_<value>` takes each member's handler; a member named like a handler is heard only through `on_message`. An operation without typed events or messages reads as before.
- **The Go SDK types event streams and sockets from the document.** An SSE operation with named events yields `<Op>Event`, a sealed interface with one type per name, each holding `SSEEvent[Data]` with its JSON parsed by the name, and `<Op>OtherEvent` for a name the operation does not declare; `Untyped()` reads any event's data as text. A WebSocket operation with declared messages returns `TypedWebSocket[In, Out]` and a realtime one `ResumableConnection[In, Out]`, with `OnMessage` beside the reader. When the messages are a union keyed on one field, the answer is `<Op>Socket` or `<Op>Connection`, whose `On<Value>` takes each member's handler, and a value the operation does not declare reads as `<Op>OtherMessage`; a member named like a socket handler is heard only through `OnMessage`. A generated CLI prints a typed message as its JSON. An operation without typed events or messages reads as before.
- **The Python SDK types event streams and sockets from the document.** An SSE operation with named events yields `<Op>Event`, a union of `SseEventOf[Literal[name], Data]` that mypy narrows on `event`, each JSON event parsed by its name; an unnamed event reads `event == "message"`. A WebSocket operation with declared messages returns `TypedWebSocket[Out, In]` and a realtime one `ResumableConnection[Out, In]`, with `on("message")` beside the reader. When the messages are a union keyed on one field, the answer is `<Op>Socket` or `<Op>Connection`, whose `on("<value>")` takes each member's handler; a member named like a socket event is heard only through `on("message")`. An operation without typed events or messages reads as before.
- **The TS SDK types event streams and sockets from the document.** An SSE operation with named events yields `SSEEventOf<{ name: Data }>`, a union keyed on `event` with each `data` typed and its JSON parsed by event name; an unnamed event reads `event: "message"`. A WebSocket operation with declared messages returns `TypedWebSocket<In, Out, K>`: `send` takes what the server receives, as JSON, `on("message")` hears what it sends, parsed, and a frame that is not JSON reaches `on("error")`. A realtime operation returns `ResumableConnection<T, In, K>` with `on` and `off` beside its iterator. When the messages are a union keyed on one field `K`, `on("<value>")` hears each member; a member named like a socket event is heard only through `on("message")`. An operation without typed events or messages emits what it did before.
- **The reader takes typed stream shapes.** `toIR` reads an OpenAPI 3.2 `text/event-stream` `itemSchema` into each response's named `events` (an event with no `event` const is `message`, its `data` from `contentSchema` when present), and the rich `x-websocket` object, on WebSocket and realtime operations, into the operation's `receive` and `send` `messages`. An operation with the object form is a WebSocket operation, as one with `x-websocket: true` is. No generated SDK, CLI or MCP server changes yet.
- **installgen ships inside the package.** The `installgen` command (`init`, `build`, `check`) and the `@workerstack/clients/installers` subpath replace `@lovrozagar/installgen`. A generated CLI's `release.yml` now runs `npx --yes --package @workerstack/clients@<version> installgen check`, from the same release that wrote its installers.
- **Release tooling ships inside the package.** `honey-clients release bump|sync|bootstrap|codegen|toolchains --config <path>` and the `@workerstack/clients/release` subpath version, mirror and publish the packages a `release.config.ts` lists. `release codegen` runs the config's codegen as `bump` does, and `release toolchains` prints the `system.config.ts` names that codegen needs, from the config's new `toolchains` field.
- **Reusable release workflows.** `release-validate.yml`, `release-sync.yml` and `release-bump.yml` in this repository are callable as `workerstack/clients/.github/workflows/<name>.yml@workflows-v1`; they install the consumer's toolchains and run its codegen before they validate, mirror or open the release PR. [`references/release.md`](https://github.com/workerstack/clients/blob/main/references/release.md) is the release guide. They need this release or later in the consumer.
- **A TS client reports what each write made stale through `onInvalidate`.** `onInvalidate` takes a list of hooks, beside `onRequest` and `onResponse`. They are called once per successful write (after its final answer, an auth refresh or retry included, or a 2xx whose body does not decode) with `{ by, targets }`: the write's operationId, and each read its `x-invalidate` makes stale as `{ operationId, params }` with the write's own values for that read's path params. Selectors are resolved when the SDK is generated (`{id}` and `:id` match, `*rest` matches a wildcard, `:id?` names both reads); one that matches no GET read is a generation notice. Hooks run in order and the write resolves after the last; a hook's error goes to `onLog` and never changes the write's result. An event stream or WebSocket calls them when it opens, without waiting. The generated config narrows `by` and each target's `operationId` to the document's ids.
- **A Go client reports what each write made stale through `OnInvalidate`.** `Config.OnInvalidate` takes a list of `func(context.Context, InvalidateEvent) error` hooks, called once per successful write (after its final answer, an auth refresh included, or a 2xx whose body does not decode or runs past the cap) with `InvalidateEvent{By, Targets}`: the write's operationId, and each read its `x-invalidate` makes stale as `InvalidateTarget{OperationID, Params}` with the write's own values for that read's path params. Selectors resolve at generation as in TS; one that matches no GET read is a `go:` generation notice. Hooks run in order with the caller's context, and the call returns after the last; a hook's error goes to `OnLog` and never fails the call, the `Safe()` twin included. An event stream or WebSocket marks its targets stale and calls the hooks when it opens, without waiting.

### Changed

- **Breaking: The Python SDK's stream classes are generic in what they read and send.** `TypedWebSocket` is `TypedWebSocket[Out, In]` and `ResumableConnection[T]` is `ResumableConnection[Out, In]`; an annotation that spelled the bare class writes `TypedWebSocket[str | bytes, object]` or `ResumableConnection[T, object]`. `SseEvent[T]` stays, now an alias of `SseEventOf[str | None, T]`. An operation with declared messages sends every value as JSON, text too, and a frame that is not JSON raises `DecodeError` from `recv()` instead of reading as text. [The migration guide](docs/migration.md) has each signature before and after.
- **Breaking: The Go SDK's stream types are generic in what they read and send.** `TypedWebSocket` is `TypedWebSocket[In, Out]` and `ResumableConnection` is `ResumableConnection[In, Out]`; a type that spelled the bare one writes `TypedWebSocket[[]byte, any]` or `ResumableConnection[any, any]`. The socket's `On(event, func([]byte))` is replaced by `OnMessage`, `OnClose` and `OnError`, and a custom `Transport`'s `Recv` returns bytes. An operation with declared messages sends every value as JSON (`SendText` sends text), and a frame or message that is not JSON is a `*DecodeError`, the socket and the connection still open. Typed SSE data that does not decode is a `*DecodeError` too. [The migration guide](docs/migration.md) has each signature before and after.
- **Breaking: The Rust SDK's stream types are generic in what they read and send.** `TypedWebSocket` is `TypedWebSocket<In, Out>`, `ResumableConnection` is `ResumableConnection<In, Out>` and `EventStream` is `EventStream<E = SseEvent>`, each defaulting to the untyped one; an untyped stream is `EventStream`, a typed one `EventStream<SseEvent<T>>`. The socket's `WsEvent` and `on(event, FnMut(&[u8]))` are replaced by `on_message`, `on_close` and `on_error`, and `send_json(&T)` by `send(&Out)`, which on an untyped socket or connection takes a `serde_json::Value`. An operation with declared messages sends every value as JSON (`send_text` sends text), and a frame or message that is not JSON is `Error::Decode`, the socket and the connection still open. `ResumableConnection::connect` opens only the untyped connection. [The migration guide](docs/migration.md) has each signature before and after.
- **Breaking: The C# SDK's stream types are typed in what they read and send.** `EventStream<TEvent>` yields the event itself, so an untyped stream is `EventStream<SseEvent<string>>` (was `EventStream<string>`) and a typed one `EventStream<SseEvent<T>>`. `ResumableConnection<T>` is `ResumableConnection<TIn, TOut>`; an operation without messages spells `ResumableConnection<T, JsonElement>`, or `ResumableConnection<JsonElement, JsonElement>` without an event schema either. The realtime `SendAsync<TValue>(TValue, JsonTypeInfo<TValue>)` is replaced by `SendAsync(TOut)`. The untyped `TypedWebSocket` keeps its spelling and its API. An operation with declared messages sends every value as JSON (`SendAsync(string)` sends text), and a frame or message that is not JSON is a `DecodeException`, the socket and the connection still reading. [The migration guide](docs/migration.md) has each signature before and after.
- **Breaking: The Java SDK's stream types are typed in what they read and send.** `EventStream<E>` yields the event itself, so an untyped stream is `EventStream<SseEvent<String>>` (was `EventStream<String>`) and a typed one `EventStream<SseEvent<T>>`. `TypedWebSocket` is `TypedWebSocket<TIn, TOut>` and `ResumableConnection<T>` is `ResumableConnection<TIn, TOut>`; Java has no default type parameters, so an operation without messages spells `TypedWebSocket<WsMessage, JsonNode>` and `ResumableConnection<JsonNode, JsonNode>`. `sendJson(Object)`, `send(String)` and `send(byte[])` are replaced by `send(TOut)`, `sendText` and `sendBinary`, so an old `send("raw")` no longer compiles; an untyped `send` takes a `JsonNode`. An operation with declared messages sends every value as JSON, and a frame or message that is not JSON is a `DecodeException`, the socket and the connection still reading. [The migration guide](docs/migration.md) has each signature before and after.
- **Breaking: A realtime connect takes its reconnect options as one value, in Go, Python, Rust and C#.** The resume cursor, the offered subprotocols and the reconnect policy are no longer flat options beside the operation's own: pass them as `Transport: sdk.TransportOpts{...}` in Go, `transport=TransportOpts(...)` in Python, `transport: TransportOpts { .. }` in Rust and `transport: new() { ... }` in C#. The connection advances its own copy, so the value you pass is never changed; resume from `conn.Cursor()` in Go, `conn.opts` in Python, the connection's `last_event_id()` and `reconnect_token()` in Rust and `rc.Options` in C#. The flat names were too long for each language's per-operation budget, and they clashed with an operation's own parameters of the same name. A generated Go CLI's flags are unchanged.
- **Breaking: A TS WebSocket call takes no `headers` or `cookies`.** A browser socket cannot send them, so the input no longer offers them, even when the upgrade declares them; send credentials in the query or a subprotocol. The generated ws ctx in `types.gen.d.ts` now types the upgrade's `input.headers` and `input.cookies` as the backend validates them.
- **Breaking: Handlers are typed by operationId, and taps are defined (1.0.0-rc.28).** `types.gen.d.ts` fills `@workerstack/backend`'s `HttpCodegen` `operationId` slot: each declared id maps to its kind and context, so a helper takes `OperationCtx<"users.list">` from `@workerstack/backend/http` and `invalidate` takes HTTP ids. `RouteCtx` and `RouteSelector` (in `types.gen.d.ts` and `routes.gen.ts`) are no longer emitted. `Routes` and the other `Route*` extractors stay. The string-keyed `ctx.tap(key, payload)` and its `TapMap` are gone: register a tap from `defineTap` and call `ctx.tap(tap, payload)`. Every route needs an operationId, as the backend's document requires.
- **Breaking: Every honey name is gone (1.0.0-rc.27).** The bin is `clients` (was `honey-clients`), the env vars are `CLIENTS_*`, the source condition is `backend-source`, the wire names are `x-backend-*`, and the generated SDKs are named for the target: `HttpSdk`, `http_sdk`, `HttpException` and the rest. There are no aliases. Upgrade together with `@workerstack/backend` 1.0.0-rc.26, rerun `clients generate`, and use [the migration guide](docs/migrating-from-honey.md), which maps each old name to its new one.
- **Generated code imports the backend by surface.** `@workerstack/backend` 1.0.0-rc.26 has no root entry, so the generated `types.gen.d.ts`, route trees and the IR loader import `@workerstack/backend/http` and `/http/openapi`. Upgrade both packages together and rerun `honey-clients generate`; [the backend's migration guide](https://github.com/workerstack/backend/blob/main/docs/migrating-from-honey.md) maps every moved import.
- **The package has its own repository.** `@workerstack/clients` now ships from [github.com/workerstack/clients](https://github.com/workerstack/clients), with its full history. The move itself changed nothing in the package: 1.0.0-rc.24 has rc.23's `honey-clients` command, exports and generated code. It depends on `@workerstack/backend` only for its tests, and an app keeps both as before.
- generate --app on Node loads the module through Vite's module runner instead of jiti: vite is an optional peer it needs there, and installing clients no longer pulls in jiti

### Fixed

- **Installing the package runs no script.** 1.0.0-rc.30 shipped this repository's `postinstall` (`repo sync`), which fails wherever `@workerstack/repo` is not installed, so every install of it failed, `npx --package @workerstack/clients installgen` included. The published manifest now lists no scripts.
- **The C# WebSocket dial opens when the server marks its 101 with a content coding.** `wrangler dev` answers an upgrade that offers gzip with `Content-Encoding: gzip` on its `101 Switching Protocols`, and the default handler's automatic decompression put a read-only decoder over the connection, so every socket and realtime dial failed with `ArgumentException: The base stream is not writeable`. A 101 has no body: its content is the connection, so the dial now takes it from beneath a gzip or br decoder, from the default handler or a `ClientConfig.Handler`. .NET's deflate decoder exposes no connection, so a 101 marked `deflate` fails the dial with `ApiConnectionException`.
- **The published manifest names only versions npm can install (1.0.0-rc.28).** 1.0.0-rc.27 listed its vendored backend tarball as a `file:` devDependency. The manifest now lists no devDependencies, which an install never reads, and a `file:`, `link:` or git spec in `dependencies`, `optionalDependencies` or `peerDependencies` fails the pack.
- **A sub-app mounted with `.route()` is typed at its mounted path.** `types.gen.d.ts` typed a route registered on a sub-app at the sub's own path (`GET /`), so a mounted route lost its middleware additions, input and params, and generate said "extracted ctx additions match no documented operation". The extractor now follows each app to its `.route(prefix, sub)` and `.route(sub)` mounts, whether the sub is built as a chain or by statements, imported or returned from a function, and nested mounts compose. A sub reached only through a function parameter keeps its own path, and a mount whose path is no literal type says so.
- **A handler's own ctx fits its generated `OperationCtx`.** With no `metaType` declared, the generated ctx typed `meta` as the tree's literal values, which the handler's own ctx does not have, because `.meta()` widens each value, so `function list(c: OperationCtx<"hello.list">)` refused the handler's `c`. The ctx's `meta` is now `Partial<HttpMeta>`, and the literals stay the route's sibling `meta` field. A route served through a mount no longer types `ctx.routePattern` as the mounted pattern, which its handler, typed at the sub's own path, cannot match. That key is now the base context's `string`. `ExtractedTypes` gains `mounted`, the ids served that way.
- **A GitHub release's live check has the job's token.** The rendered `release.yml` step that confirms a `github` registry's release ran `gh release view` without `GH_TOKEN`, so it failed in Actions after the release was created. It now gets `GH_TOKEN: ${{ github.token }}` like the publish step. The release guide also lists `administration: write` for the sync App, which sync needs to set a repo's description, homepage and topics.
- Generated TypeScript, the types `backend generate` extracts from an app among it, types an optional property `k?: T | undefined`, and the MCP runtime's optional fields say `| undefined` too, so a consumer under `exactOptionalPropertyTypes` accepts the `undefined` a zod `.optional()` infers.
- **The package ships its reference pages.** `references/` is in the tarball and exported as `@workerstack/clients/references/*`, so an agent or tool reading the installed package finds the same CLI, flag and SDK references the repository has.
